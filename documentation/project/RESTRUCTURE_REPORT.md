# RESTRUCTURE_REPORT: SomBill full-project restructure

_22 Nov 2026. Every number below comes from commands run on the project, before and after the change._

## 1. Original architecture (as found)

```text
SomBill Project/
├── backend/                      EMPTY
└── frontend/
    ├── SomBill-Website/          public website: Vite app, React 19 / Tailwind 4, no lockfile (34 files)
    └── SomBill-Dashboards/       Manager + Waiter + Cashier in one Vite app, React 18 / Tailwind 3 (163 files)
        ├── manager/ waiter/ cashier/ shared/ routing/ e2e/      (already well organized internally)
        ├── documentation/        module guides, test reports, PROJECT_STATUS, an earlier restructure report
        └── supabase/             ← the entire backend: 7 migrations, RLS, Edge Function, 303 SQL tests
```

197 files in total, about 2.4 MB without dependencies. No Git repository, `node_modules` or build output was present.

## 2. Problems identified

| # | Problem | Severity |
|---|---|---|
| 1 | **Wrong frontend/backend boundary.** `backend/` was empty, and the whole backend (schema, RLS security model, business-logic SQL, the service-role Edge Function, database tests) lived inside a frontend app folder. | High |
| 2 | **One cross-boundary import.** `manager/__tests__/manageStaff.test.ts` imported `../../supabase/functions/manage-staff/handler`, so a frontend test suite tested server code. | Medium |
| 3 | **Backend tooling owned by the frontend.** `npm run test:db` was a dashboards script. ESLint and `.gitignore` in the dashboards carried backend-only exceptions (`supabase/functions`, `supabase/.temp`). | Low |
| 4 | **Documentation split by accident.** Project-wide status and database test reports sat inside the dashboards app; the website guide sat inside the website app; there was no project-level README or architecture document. | Medium |
| 5 | **No project root.** No root README, `.gitignore` or single command to build and verify everything. | Medium |
| 6 | **Non-reproducible website installs.** The website had no `package-lock.json`, so `npm install` could resolve different versions on each machine. | Medium |
| 7 | **Redundant folder names.** `frontend/SomBill-Website` and `frontend/SomBill-Dashboards` repeat the project name inside the project. | Low |

**Checked and found fine** (no change made):

- **Duplicates:** no two files are byte-identical. The 10 file names that occur in both apps (`App.tsx`, `main.tsx`,
  `index.html`, `package.json`, `vite.config.ts`, `tsconfig.json`, `README.md`, `.gitignore`, `.env.example`, and
  `navigation.ts` in the three dashboards) are each app's or dashboard's own file, with different content and purpose.
  Nothing was consolidated or deleted.
- **Dashboard boundaries:** no dashboard imports another dashboard, and `shared/` imports nothing dashboard-specific.
  The earlier internal restructure (kept in `history/`) had already fixed this.
- **Website internals:** the `src/` layout was already sound.
- **Secrets:** only `.env.example` files and `.env.e2e` (fake values for the offline test) exist. No real keys were found.

## 4. Frontend restructuring

- **Website:** moved as a unit to `frontend/website/`. Its `documentation/` moved to `documentation/website/`, and a
  `package-lock.json` was added (generated by `npm install` from the unchanged `package.json`). The README now shows
  the folder path, links to the guide and uses `npm ci`. **No source file changed.**
- **Dashboards:** moved as a unit to `frontend/dashboards/`, so every internal import (`@/…` alias and relative) still
  resolves unchanged. `supabase/` moved to `backend/` and `documentation/` to `documentation/`. Internal folders
  (`manager/`, `waiter/`, `cashier/`, `shared/`, `routing/`, `e2e/`) are untouched.
- **Shared frontend resources:** no cross-app `frontend/shared/` was created. The two apps use different React,
  Tailwind, Vite and TypeScript majors and have no functional overlap (see `frontend/README.md`). Dashboard-shared code
  stays in `frontend/dashboards/shared/` (40 modules, plus test helpers).

## 5. Backend restructuring

- `frontend/SomBill-Dashboards/supabase/` → `backend/supabase/`, **byte-identical** (16 files). The Supabase CLI
  layout (`migrations/`, `functions/<name>/`) is preserved, so `supabase db push` and `supabase functions deploy` work
  from `backend/`.
- `manager/__tests__/manageStaff.test.ts` → `backend/tests/functions/manage-staff.test.ts`, byte-identical. Its
  relative import `../../supabase/functions/manage-staff/handler` still resolves because the depth is the same.
- New `backend/package.json` (Vitest 2.1 and TypeScript 5.6, the versions the dashboards already use), `tsconfig.json`
  (strict, `ES2022` and `DOM` libs for the `URL` global that Deno provides), `vitest.config.ts` and `.gitignore`.
- No Express-style folders were introduced. There is no Express code, and the backend's layers are SQL functions, RLS
  and one Edge Function. `backend/README.md` maps the usual layers onto them.

## 6. Shared components consolidation

No website and dashboard pair qualifies for sharing (section 4).

## 10. Remaining items and recommendations

1. **Logo for the dashboards.** The website has `frontend/website/public/images/sombill-logo.jpeg`. The dashboards
   look for `frontend/dashboards/shared/assets/branding/sombill-logo.png` and show a text wordmark until it exists. It
   was not copied, because that would change the dashboards' UI. If it is the official logo, save it as that PNG.
2. **`supabase/config.toml` is missing.** Run `supabase init` in `backend/` before `supabase link`. It does not touch
   the migrations or functions.
3. **Website bundle size.** Vite warns that one website chunk is over 500 kB. This was already the case and is not
   caused by the restructure. Lazy-loading the simulator sections would fix it.
4. **Version control.** The project is not a Git repository. `git init` at the root is recommended. The root
   `.gitignore` already excludes dependencies, builds, env files and the local backup folder.
5. **Backup folder.** `_backup_original_2026-11-22/` holds the untouched original. Delete it once you have checked the
   new layout. It is excluded from the ZIP.
